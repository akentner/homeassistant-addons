<objective>
Prove the bearer-listener architecture end to end on one path before anything else, and pin the ingress server's
observable behaviour before plan 02 refactors it.

Purpose: The phase goal is "an add-on can serve a JSON API on its own port that only answers requests with a valid
bearer token, using the same Router, Request, ApiError and error codes as the ingress GUI". The tracer wires one GET
through every layer the phase adds (option token -> bearer gate -> shared JSON base -> Router -> JSON response) over a
real socket, so an architectural dead end shows up after one commit. The characterisation test is the safety net that
makes "the ingress handler's observable behaviour stays identical" (CONTEXT Claude's Discretion, D-02) provable.

Output: `skeleton/api.py`, `skeleton/tokens.py`, `_JsonHandler` in `skeleton/server.py`, lib `VERSION` 0.10.0 with a
fresh `lib.lock`, `tests/test_api_server.py` (tracer tests), `tests/test_ingress_characterisation.py`.
</objective>
