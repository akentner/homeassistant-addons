the add-on log line `store: {owner/repo} registered as {slug} (...)`; after updating to this version the proxy registers its configured repositories automatically while `register_local` is true; the URL depends on the install source's hostname, so switching between a local copy and this repository's install, or restoring under another repository, gives a second store repository that is reported as an `orphaned` leftover); the Supervisor refuses while add-ons installed from it exist; the old URL then keeps serving so those add-ons keep getting updates (Q-2); procedure: back up the add-ons' data, reinstall them from the new store repository, uninstall the old ones, then `mrp local remove {owner/repo}`; `--revoke-old` stops the old URL at once and uninstalls nothing); `### Removing the store repository` (`mrp local remove {owner/repo} [--revoke-old]`: retries leftovers; removes the current registration only when `register_local` is false or the repository is no longer configured, otherwise `error: register_local_enabled`; `register_local: false` and removing a repository from `repositories` remove nothing by themselves (Q-3); removing the store repository in the Supervisor UI or with `ha store delete` also works, the proxy cleans up its own state at the next sync); `### Leftovers` (table of reasons `in_use`, `error`, `interrupted`, `orphaned` with meaning and fix; never removed automatically; `mrp local status` and `/data/supervisor.json` show them).
- `## Managing users`: `local` and `local.*` are reserved for the add-on's own store registration; `mrp users revoke ... local` answers `error: user_reserved`; point to `## Store registration`.
- `## Contracts`: new `### /data/supervisor.json` (single writer: the sync process; atomic replace, mode 0600; holds store slugs and masked URLs, never a full hash or token; later versions may add fields, never rename them) with a JSON example using placeholders (`{8 hex}`, masked `abcd…` style) and a field table for `schema`, `updated`, `register_local`, `hostname`, `supervisor.last_contact|last_status|last_error`, `reload.last_requested|last_result|pending|message`, `repositories[].repository|configured|registration (registered|pending|disabled|failed)|store_slug|masked_url|registered_at|last_checked|message`, `leftovers[].repository|store_slug|user|masked_url|since|reason|message|revoked`, `requests[].id|action|repository|result (done|refused|failed|rejected)|code|finished` (last 20); new `### Supervisor requests` (internal queue `/run/marketplace-repo-proxy/supervisor.requests/`, written only by `mrp local`, executed by the sync process one at a time; not an API for other tools).
- `## Security notes`: new item "Supervisor manager role": the add-on uses `hassio_api: true` and `hassio_role: manager` because the store endpoints are manager-only; the role would also allow add-on control, backups, Core, host, OS and Supervisor endpoints; the add-on uses only four calls (`GET`/`POST /store/repositories`, `DELETE /store/repositories/{slug}`, `POST /store/reload`), checked before any network I/O; the token is used only by the sync process and never reaches the web server, access-watch or the `mrp` command; every call is logged without secrets; the Supervisor's security rating of the add-on is 6 instead of 7; the Supervisor's own log shows registered store URLs in full, so access to that log equals access to the `local` URLs; a refused removal makes the Supervisor log a traceback and, with diagnostics enabled, send an error report.
- `## Limitations`: the add-on talks to the Supervisor's TCP API with its token; newer Supervisor versions add a per-add-on socket, which a later version may use (Q-6).
