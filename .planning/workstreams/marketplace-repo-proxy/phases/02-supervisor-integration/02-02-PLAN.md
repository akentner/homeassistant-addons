<objective>
Make upstream changes reach the local store within minutes (MRP-09): detect a real head change against the previous
`status.json`, send one `POST /store/reload` per sync interval at most, and never lose a deferred reload, not even
across a restart.

Purpose: the Supervisor only pulls every 3 hours; the proxy knows when refs changed (D-08). Comparing against the
carried head instead of Phase 1's `refs_changed` avoids a reload storm on every container start (RESEARCH Pitfall 1).
Output: `StatusWriter.head_changes`, the reload gate in `Registrar`, the `reload` section of `/data/supervisor.json`,
the `supervisor` wake-up reason in the sync loop, unit tests. The container proof is Plan 05.
</objective>

## Confirmed decisions and assumptions (for user confirmation)

Locked decision implemented: D-08 (reload after changed refs, at most once per interval, failed reload retried no
earlier than the next allowed window).

Planner assumptions (confirm or correct):

- **A-6 Change signal:** "refs changed" = served head differs from the head carried in `/data/status.json` (RESEARCH
  Pitfall 1); Phase 1's `refs_changed` field keeps its meaning for the GUI but does not drive reloads.
- **A-7 Reload scope:** only a change of a repository whose `local` URL was already `registered` triggers a reload; URLs
  of other users that an operator added to this Supervisor by hand are not tracked (the proxy cannot see them without
  matching every user's URL against the store list).
- **A-8 Persistence:** `reload.pending` is persisted in `/data/supervisor.json`; the rate-limit clock itself is
  in-memory, so the first window after a restart is open.
