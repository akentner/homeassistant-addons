## Assumptions (flagged for user confirmation)

- The fake Supervisor reproduces the parts of the real one that the proxy depends on (clone on add, 409 duplicate, 400
  refusal with the full URL, 404 on unknown slugs, reload pulling every custom repository) from the Supervisor source
  quoted in 02-RESEARCH.md; the live run in Plan 07 checks the real behaviour.
- A container recreate (`docker rm -f` + `docker run` with the same `/data` and hostname) is the stand-in for an add-on
  restart or update on a real host, which recreates the container (RESEARCH A3).
- The verify run takes longer than in Phase 1 (two recreates, one restart); no `sleep` waits for the 5-minute reload
  window, the pending path is proven through the recreate instead.
- Disconnecting the fake Supervisor from the verify network is the stand-in for an unreachable Supervisor (D-28
  `error`); the fake keeps its in-memory state, so reconnecting it under the alias `supervisor` restores the store.
