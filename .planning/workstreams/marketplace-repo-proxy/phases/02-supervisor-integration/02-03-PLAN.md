<objective>
Give the operator a safe way to remove the `local` store repository (MRP-10, removal half): `mrp local remove` queues a
request, the sync process makes the allow-listed `DELETE`, a refusal by the Supervisor becomes a recorded leftover that
is never forced and never retried in a loop, and the CLI can no longer orphan a registered store repository by revoking
the `local` user by hand. Also adds the access-store primitives the rotation in Plan 04 needs.

Purpose: D-09/D-10 (refusal reported, leftover recorded for the Phase 3 GUI), D-02/D-03 (the CLI must never use the
token although `docker exec` hands it the container environment).
Output: reserved-label guards and retire/undo primitives in `app/access.py`, `mrp local status|remove`, the request
queue and removal executor in `app/registration.py`, `leftovers[]`/`requests[]` in `/data/supervisor.json`, tests.
</objective>

## Confirmed decisions and assumptions (for user confirmation)

Locked decisions implemented: D-02/D-03 (CLI never calls the Supervisor), D-09 (refusal reported, never forced, never
retried in a loop, nothing uninstalled), D-10 (leftover recorded machine-readably and logged at warning).

Open questions planned with the recommended variant (confirm or correct):

- **Q-3 Removal triggers:** no automatic removal. `register_local: false` only stops adding; removing a repository from
  `repositories` leaves its store repository in place. Removal is the explicit `mrp local remove`, allowed for the
  current registration only when `register_local` is false or the repository is unconfigured (otherwise the next pass
  would re-add a new URL). When the operator deletes the store repository elsewhere (`ha store delete`, Supervisor UI),
  the next pass cleans up the proxy's own state.
- **Q-7 Refusal noise:** D-02's four calls stay; no pre-check through `GET /store`. A refused `DELETE` makes the
  Supervisor log a traceback (and send a Sentry event when diagnostics are on); this happens only on explicit operator
  actions, never in a loop.

Planner assumptions:

- **A-9 Request queue:** operator actions reach the sync process as request files in
  `/run/marketplace-repo-proxy/supervisor.requests/` (tmpfs, lost on restart by design); the CLI waits up to 30 s for
  the result and otherwise prints `queued`.
- **A-10 Retry semantics:** `mrp local remove` always retries the repository's leftovers first; with
  `register_local: true` it touches nothing else.
