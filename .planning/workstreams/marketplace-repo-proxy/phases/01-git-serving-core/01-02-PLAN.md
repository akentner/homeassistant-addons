<objective>
Expand the tracer's sync into the full MRP-02 service: classify upstream failures into stable status codes, inspect
HEAD for `repository.yaml` and add-ons, keep refs clean on branch changes, publish everything in `/data/status.json`
(the Phase 3 GUI contract), and run cycles on the interval and on the "Sync now" trigger file.

Purpose: an operator (and later the GUI) can see why a repository is not served, and an upstream push reaches the
store URLs at the next sync or immediately on request.
Output: `app/status.py`, extended `app/gitops.py` and `app/sync.py`, test fixture helper and three test files.
</objective>

## Assumptions (flagged for user confirmation before execution)

- **A-2:** status.json adds `pending` (configured, never attempted) and `fetch_failed` (network/timeout/other) to
  D-14's four codes. The four D-14 codes keep their meaning; both additions are additive.
- A valid PAT without access to a repository is assumed to yield GitHub's 404 (`not_found`); with a bad token GitHub
  answers 401 even for missing repositories, so it is always `auth_failed` (RESEARCH A1).
- A stopped sync (SIGTERM) finishes the running git command and stops between repositories; s6's kill timeout
  bounds the wait.
