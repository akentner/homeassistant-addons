<objective>
Tracer-first: prove the whole Phase 1 architecture end to end on the clone path only, then add the operator's entry
point. One configured private repository is synced with a PAT from a local auth-checking upstream fixture into a bare
repository, one user entry is placed in `/data/access.json` before the container starts (the hand-edit route that
ROADMAP criterion 4 also uses), `init` links it, and a second container clones the user's store URL `--depth 1`
through lighttpd + `git http-backend`. Task 2 adds `mrp users add` (hash generation, URL output) with unit tests.

Scope note (context budget): the tracer carries only what the clone path needs. The CLI and URL helpers are Task 2;
the startup log, the init failure policy, the options/logging regression tests and the CI job are Plan 04 (wave 2).
Task 1 still lists 28 files because s6-rc needs one directory per service: 10 are declaration files without logic
(`type`, `up`, empty dependency and bundle markers), 6 are one- to ten-line files (`run.sh`, the s6 `run`/`finish`
scripts, `app/__init__.py`), and 12 carry real content (config.yaml, Dockerfile, lighttpd config, 8 Python modules,
verify script). Two of the 8 modules (`paths.py`, `logsetup.py`) are copies of exact analogs.

Purpose: catch an architectural dead end (s6 layout, lighttpd allow-list, symlink authorization, PAT-in-env sync)
after one commit instead of after six plans. Plans 02, 03 and 04 build on the module contracts fixed here.
Output: working add-on image, Python package `app/`, s6 services `init`/`lighttpd`/`sync`, `mrp users add`, first
version of `internal/verify-marketplace-repo-proxy.sh`, test harness with URL and CLI tests.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git client / other add-on -> lighttpd :8080 | Untrusted HTTP requests on the hassio network; the hash is the only secret |
| lighttpd CGI -> filesystem | `git http-backend` runs as `lighttpd`, resolves symlinks under `/srv/git/access` |
| sync -> upstream (GitHub or test fixture) | PAT leaves the process only as an HTTP header of the git child |
| add-on options -> Python | Supervisor-validated values become paths and refspecs |
| container env -> services | Test override and (Phase 2) Supervisor token live in the container environment |
