# Quick Task 260927-q51: `printer_presets` as a Top-Level Object List Summary

**Replaced the flattened-string `printers[].presets` AirPrint preset config with a top-level `printer_presets[]` object list ({printer, name, options}), a deliberate breaking change with no migration shim.**

## Performance

- **Duration:** ~20 min (includes a full empirical Docker-based verification run)
- **Tasks:** 3/3 completed
- **Files modified:** 5 (`cups/generate_config.py`, `cups/config.yaml`, `internal/verify-cups-scaffold.sh`, `cups/DOCS.md`, `cups/README.md`)

## Accomplishments

- `cups/generate_config.py`: deleted `_parse_presets_field()`; `build_preset_injection_snippet()` now accepts a pre-grouped `list[tuple[str, str]]` instead of parsing a flattened string itself; new `group_presets_by_printer()` groups the top-level `printer_presets` option list by its `printer` FK; `build_printer_registration()`'s two call sites (brlaser + generic branches) read from `presets_by_printer.get(name, [])`; `main()` warns once per `printer_presets` entry whose `printer` FK never matched a registered printer
- `cups/config.yaml`: `presets: str?` removed from the `printers:` schema list; new top-level `printer_presets` schema (list of `{printer: str, name: str, options: str}`) + `printer_presets: []` default added
- `internal/verify-cups-scaffold.sh`: fixture reshaped — both printers' preset fixtures moved from `printers[]` into the new top-level `printer_presets` array (same names/values), plus a throwaway unmatched-FK entry (`nonexistent-printer` / "Ghost Preset"); two new assertions prove the unmatched FK is WARNING-logged and never appears in the generated `register-printers.sh`
- `cups/DOCS.md`: `### Printer presets` subsection replaced with a new top-level `## Printer Presets` section (worked example, `printer` FK explanation, discovery guidance via `lpoptions -p <printer> -l`, explicit breaking-change note, schema-depth rationale); `## Design notes` paragraph rewritten; Add-on Options + Printers tables updated
- `cups/README.md`: Features bullet rewritten for the new top-level list shape
- Version bumped one subpatch to `0.1.0-11` via `make update-version ADDON=cups VERSION=0.1.0-11` (explicit full string, never bare `X.Y.Z`)

## Decisions Made

- Deliberate breaking change: `printers[].presets` removed entirely, no migration shim — matches the plan's explicit instruction and the user's own stated rationale (the old flattened-string format already caused a real config mistake via a stray literal `"` pasted into the HA UI's YAML editor)
- `printer_presets` hoisted to a top-level list (sibling of `printers[]`), not nested inside it, because HA's add-on options schema micro-language caps nested list/dict depth at two and `printers[]` already uses both levels — re-confirmed against the HA add-on configuration docs, not re-litigated
