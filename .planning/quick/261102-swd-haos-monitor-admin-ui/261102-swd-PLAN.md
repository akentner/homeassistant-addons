<objective>
Rebuild the haos-monitor status page on the shared admin-ui blueprint stack: a Preact page on the synced lib, served by a
Python server built from the synced skeleton, behind the ingress gate, on its own internal port. The machine endpoints
stay on 8099 exactly as they are.

Purpose: haos-monitor is the second consumer of the blueprint (user decision 2026-11-02, admin-ui DOCS "Migration paths
> haos-monitor"). The old page is a 140-line inline-script HTML file in a busybox/CGI add-on, served unauthenticated on
the optional published port. After this task it follows the repository rules R-01..R-15 (ingress gate, relative URLs, no
state in markup, i18n with parity, tokens and themes, tests in CI), and the published port no longer exposes a GUI.
Output: GUI server in `haos-monitor/app/`, synced lib and skeleton copies, Preact views with German and English
strings, node and pytest suites, a CI job, Dockerfile/run.sh/config changes, docs, CHANGELOG and version 0.7.0-0.

Locked decisions (the user's brief of 2026-11-02; there is no CONTEXT.md in quick mode, so they are labelled here for
traceability):

- D-01: TWO PORTS. The new GUI runs on the skeleton behind the ingress gate on its own internal port;
  `config.yaml` `ingress_port` switches to it and it is never published. `/api/status.json`, `/cgi-bin/status`,
  `/api/metrics.txt`, `/cgi-bin/metrics`, `/api/hosts.json` and `/api/incidents.json` stay UNCHANGED on 8099 (busybox

Planner decisions (Claude's discretion, justified once so the executor does not reopen them):

- P-01 Data source: the server runs `status.sh <slug>` per host (argv list, no shell). It is the single producer that
  the status endpoint, metrics, MQTT and the incident marker already share, so the GUI cannot drift from Gatus. The
  alternatives lose: calling `http://127.0.0.1:8099/api/status.json` adds a network hop and makes the GUI depend on
  busybox httpd being up; re-implementing the 100-line awk parsing in Python duplicates logic and drifts. The cost
  (a few cheap forks per poll) is far below what httpd already forks per CGI request. A contract test pins the key set
  of the real status.sh output to the server whitelist.
- P-02 One aggregate endpoint `GET api/overview` instead of the 1+2N requests of the old page. It takes NO request
  parameter, so no request-supplied value can reach a path or a subprocess; the strict slug rule (D-04) is enforced on
  every slug read from the hosts file before it is used for argv or a log path. Per-host drill-down endpoints are not
  planned (the GUI does not need them; they would only add surface).
- P-03 GUI port 8100 (internal), configurable for tests through `HAOS_MONITOR_GUI_PORT`; `HAOS_MONITOR_INGRESS_REMOTE`
  overrides the gate peer like `ADMIN_UI_INGRESS_REMOTE` in admin-ui; the existing names `HOSTS_FILE`, `LOGDIR`,
  `STATUS_SH` and `ENV_FILE` are reused so tests and CGIs share one vocabulary. No CSP-off switch: the strict default
  stays (the admin-ui switch exists only for its spike).
- P-04 Incidents are found by a bounded backward block scan of `<slug>.log` (same semantics as the CGI: the current log
  only, lines containing ` INCIDENT `, last 10, 400 characters each). It stops after 10 hits, so a healthy host costs
  almost nothing; the scan is capped at 24 MiB (log rotation is 20 MiB).
- P-05 The overview carries `now_ms` (server clock). The boot time is `now_ms - (up + age) * 1000`, so it no longer
  depends on the browser clock (the old page used `Date.now()`).
- P-06 Two small display improvements that follow the blueprint rules without losing information: the uptime line shows
  boot time via `formatDateTime` plus `formatRelative` (R-07, Intl; the old hand-built "5d 1h ago" becomes "5 days
  ago"), and a port that has no probe data yet (value -1) shows a neutral "unknown" chip instead of "down".
- P-07 HA integration is wired like the demo (theme sync and bridge are created by `app.mjs`, started and disposed in an
  effect, injectable for tests; R-13: failure means the own theme). No info link (that needs the add-on slug from the
  Supervisor API, out of scope).
- P-08 Node tests use their own verbatim copies of `fakedom.mjs` and `a11y_audit.mjs` in `haos-monitor/tests/js/`
  (taken from `admin-ui/tests/js/`, never edited). That is what the newest consumer did: `secrets-sync/tests/web/js/
  fakedom.mjs` is byte-identical to admin-ui's copy. A cross-add-on import would couple two add-ons' test trees. If
  admin-ui later changes its fakedom, refresh the copy.
- P-09 Finding on D-06: `internal/validate-dockerfile-args.sh` auto-discovers every `*/Dockerfile`, and `make
  docker-build-check` globs `*/`, so neither needs haos-monitor listed. `internal/base-image-config.yaml` only drives
  the daily base-image bump (`update-base-image.py` iterates the listed add-ons); haos-monitor is not listed today and
  `admin-ui/tests/test_docs.py` asserts it stays unlisted (PD-09, follow-up). It is NOT added here; it stays on the
  follow-up list. The path-scoped pre-commit hooks `check-admin-ui-sync` and `check-admin-ui-rules` already match
  `[^/]+/app/web/...`, so haos-monitor is covered without a hook change.
- P-10 CI follows the newest consumer: the `haos-monitor` job is appended after the last line of lint.yml (after the
  `secrets-sync` job), shaped like it (comment, steps, `working-directory` for pytest, final step `make
  check-admin-ui-sync check-admin-ui-rules`). The `lint-results` report job is NOT touched: secrets-sync did not add
  itself to it either (`needs: [lint, admin-ui]` stayed), so lint.yml changes by a pure append and every zizmor
  anchor (1:1, 16:3, 22:9, 58:11, 160:3) keeps matching. A failing job still turns the workflow run red.
- P-11 `admin-ui/` and `secrets-sync/` are not touched at all, not even admin-ui's DOCS.md. Its "Migration paths"
  entries for secrets-sync (already migrated by PR #87) and haos-monitor and the Follow-up entries (secrets-sync
  rewrite, tests in CI, haos-monitor rebuild) are stale; editing them would rebuild and re-version the admin-ui add-on
  for a text change, so they are reported in the summary instead.
- P-12 The CHANGELOG heading for 0.7.0-0 is `## [0.7.0] - 2026-11-02` (the file's convention: `-0` carries no suffix,
  see `[0.6.1]`, `[0.6.0]`).

- P-13 Public routes (lib 0.5.0, `Router.add(..., public=True)`) are NOT used. D-01 keeps the machine endpoints in
  busybox httpd on 8099, so the GUI server registers no public route: its gate matrix is "every request without ingress
  is 403", `Router.is_public` is false for every route and `Request.public` is always false.
- P-14 Reference and conventions: the newest consumer, `secrets-sync` (PR #87, lib 0.5.0), is the primary wiring
  reference (`app/web/server.py` with `build_router`/`make_server` wrapping the skeleton, `tests/**/conftest.py` that

  `.dockerignore`, DOCS and CHANGELOG wording, CI job). `admin-ui` stays the reference for the Preact shell
