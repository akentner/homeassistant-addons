# Quick Task: Remove the AirPrint Print-Presets Feature

## Goal

Remove the `printer_presets` config option and all its supporting code from the `cups` add-on entirely — not
simplify it, not deprecate it, not leave a migration shim. Delete it completely.

**Why:** the user confirmed empirically (via a raw IPP `Get-Printer-Attributes` dump against the live add-on)
that Apple's `*APPrinterPreset` PPD extension is NEVER read by iOS/AirPrint at all. iOS's AirPrint client is
100% driverless/IPP-based and never parses a PPD file — this mechanism only ever mattered for macOS's classic
driver-based Print dialog. For an add-on whose entire purpose is iOS AirPrint, this feature is inert dead
weight. It was added and redesigned twice this session (quick tasks `260927-ntq`, then `260927-q51`); this task
un-ships it.

This is a pure removal task: no new behavior, no replacement mechanism. Every file that carries a trace of the
feature — schema, generator code, verify-script fixtures/assertions, docs, README — gets cleaned to zero
references, and the version bumps by exactly one subpatch.

## Security Notes

This is a pure removal, so it strictly reduces attack surface rather than adding any: `PRESET_NAME_RE` /
`PRESET_OPTION_TOKEN_RE`'s validate-before-embed gate, the heredoc-based shell-fragment generation in
`build_preset_injection_snippet()`, and the `printer_presets` schema surface are all deleted together, in one
pass, so there is no half-removed validation path left reachable from a smaller residual input surface. Nothing
else in `generate_config.py`'s T-21-01 discipline (argv-array construction, `shlex.quote`, `NAME_RE`/
`LOCATION_RE`/`DRIVER_MODEL_RE`/`ADMIN_USERNAME_RE` validation) is touched. The unrelated stable-printer-UUID
feature (`compute_stable_printer_uuid`, `PRINTER_UUID_NAMESPACE`, `import uuid`, `build_printer_uuid_fixup_script`)
must remain byte-for-byte intact — verified explicitly in T1's verify block.
