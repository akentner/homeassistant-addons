# Quick 261102: admin-ui topbar sticky, nav option, icon

Source: user feedback from the live test of the demo add-on in Home Assistant. Worker exec-26-ux1, branch
`feat/admin-ui-ux-1` (base `feat/admin-ui-blueprint` @4229996).

## Tasks

1. Icon assets: generated `admin-ui/icon.png` (128x128) and `logo.png` (250x100); Dockerfile copies `icon.png` into the
   static root so `/icon` serves it. Tests: sizes, Dockerfile line, `/icon` route returns the PNG.
2. Lib shell (`lib/shell.mjs`, `lib/base.css`, lib strings, lib 0.1.0 -> 0.2.0):
    - `.shell-head` sticky wrapper (bar + tab bar), `--safe-*` CSS variables from bridge `safeAreaInsets`, z-index 50
      (below modal 100 and toast 200).
    - `Topbar` props `views`, `activeId`, `nav` (`"topbar"` | `"tabs"`, default tabs), `navLabel`; `TopbarNav` with
      inline links, overflow measurement against a state-independent slot width (no flicker/oscillation) and a burger
      dropdown (`aria-expanded`, `aria-controls`, Escape returns focus, outside click / focus-out / link click close).
    - Kiosk coordination: the HA `toggle-menu` button stays; the nav trigger then shows the current view title so the
      two buttons never look alike.
    - `iconSrc` defaults to `./icon` (null/"" disables, load error hides).
    - Additive export `needsBurger`; export contract test and DOCS table adjusted deliberately.
3. Demo (`app.mjs`): navigation style switch, stored under `admin-ui:demo-nav` (try/catch), default `topbar`;
   de+en strings.
4. Version: lib 0.2.0 via `make sync-admin-ui`; add-on `0.1.0-1` via `make update-version` (NO_TAG, NO_PUSH).
