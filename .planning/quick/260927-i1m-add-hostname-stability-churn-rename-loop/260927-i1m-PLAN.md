# Quick Task: network-tools mdns_scan.py — Hostname-Stability (Churn/Rename-Loop) Detection

## Goal

Detect an avahi hostname-rename loop: avahi renames a service on a name conflict (e.g. `brother.local` ->
`brother-2.local`, sometimes flapping back), and a *single* poll still classifies as `online` because the new name
resolves fine — only comparing the resolved hostname **across polls** reveals the churn. Add that cross-poll
comparison to `network-tools/mdns_scan.py`, persist it the same way `arping_scan.py` already persists flap-detection
state, publish a new numeric MQTT-discovery sensor per monitor, and extend tests/docs/verify-script/version
accordingly. Scoped entirely to `network-tools/` — do not touch `cups/` or phase 21.

## Must-Haves

- [ ] `/data/state/mdns_stability_state.json` persists, per monitor slug: `last_hostname` + `hostname_change_count`
      (same atomic tmp+rename write pattern as `arping_scan.py`'s `STATE_FILE`)
- [ ] Comparison happens **only** when the current poll's classification is `online` — `not_found` /
      `announced_unresolved` / `error` polls leave the persisted baseline untouched and never count as a change
- [ ] The first-ever poll for a monitor seeds the baseline without counting as a change
- [ ] The per-monitor result dict carries `hostname_changed: bool`, `previous_hostname: str|None`, and
      `hostname_change_count: int`
- [ ] Exactly one new MQTT-discovery numeric `sensor` per monitor: `networktools_mdns_<slug>_hostname_changes`,
      `state_class: total_increasing`, `icon: mdi:swap-horizontal`, `unit_of_measurement: changes`, grouped under the
      SAME `device` block as the existing binary_sensor
  - [ ] Unit tests cover: change detected / no change / first-ever poll / non-online poll leaves baseline untouched /
      the new discovery payload builder
- [ ] `verify-mdns-monitor.sh` gains a new assertion proving `hostname_change_count` increments across two polls with
      a mocked hostname flip (9 assertions total, up from 8)
- [ ] `DOCS.md` + `README.md` document the new sensor and the specific avahi rename-loop failure mode it detects
- [ ] `network-tools` version bumped by exactly one subpatch (`0.5.0-1` -> `0.5.0-2`) via `make update-version`
- [ ] `make lint` passes

### T1: Core logic in `mdns_scan.py` — persisted state, comparison, new sensor publish

**Files:** `network-tools/mdns_scan.py`

**Action:**

Mirror `arping_scan.py`'s exact state-persistence precedent (`STATE_FILE` constant, `load_state()` returns `{}` on any
read error, `save_state()` does `mkdir(parents=True, exist_ok=True)` then atomic `.json.tmp` write + `.rename()`).
Slot the new logic into the existing structure — do not restructure `run_monitor()`, `classify()`, or the overall
per-monitor loop shape in `main()`.

1. Add a new module constant right after `OUTPUT_FILE`:
   ```python
   STATE_FILE = Path("/data/state/mdns_stability_state.json")
   ```
2. Add `load_state()` / `save_state(state)` functions (place after `load_options()`), identical in shape to
   `arping_scan.py`'s versions — `load_state()` returns `{}` on `(OSError, json.JSONDecodeError)`; `save_state()`
   writes to `STATE_FILE.with_suffix(".json.tmp")` then `.rename()`s into place.
3. Add a new function `_apply_hostname_stability(slug: str, result: dict, state: dict) -> None` (place after
   `run_monitor()`), which mutates `result` in place and updates `state[slug]`:
   - Read `entry = state.get(slug)`; `prior_hostname = entry.get("last_hostname") if entry else None`;
     `prior_count = entry.get("hostname_change_count", 0) if entry else 0`.
   - If `result["state"] != "online"`: set `result["hostname_changed"] = False`,
     `result["previous_hostname"] = None`, `result["hostname_change_count"] = prior_count`, and return — do **not**
     touch `state[slug]` at all (no seed, no reset, no increment). This is the "skip the stability check entirely"
     case from a poll with no fresh hostname to compare.
   - Else (state == "online"): read `current_hostname = result.get("hostname")`.
     - If `entry is None` (first-ever poll for this slug): seed
       `state[slug] = {"last_hostname": current_hostname, "hostname_change_count": 0}`, set
       `result["hostname_changed"] = False`, `result["previous_hostname"] = None`,
       `result["hostname_change_count"] = 0`.
     - Else: `changed = prior_hostname != current_hostname`; `new_count = prior_count + 1 if changed else
       prior_count`; write `state[slug] = {"last_hostname": current_hostname, "hostname_change_count": new_count}`;
       set `result["hostname_changed"] = changed`, `result["previous_hostname"] = prior_hostname`,
       `result["hostname_change_count"] = new_count`.
4. Add `_hostname_changes_topic_for(prefix: str) -> str` right after `_details_topic_for()`:
   ```python
   def _hostname_changes_topic_for(prefix: str) -> str:
       return f"{prefix.rstrip('/')}/hostname_changes"
   ```
5. Add `_build_hostname_changes_discovery_payload(monitor: dict, slug: str, topic_prefix: str) -> dict` right after
   `_build_discovery_payload()`. Reuse `_build_device_block(monitor, slug)` (same device block object shape as the
   existing binary_sensor, so both entities land on one HA device page) and the same `friendly` derivation
   (`monitor.get("device_name") or monitor.get("name") or slug`). Payload keys: `name` = `f"{friendly}
   Hostname-Wechsel"`, `unique_id` = `f"networktools_mdns_{slug}_hostname_changes"`, `default_entity_id` =
   `f"sensor.networktools_mdns_{slug}_hostname_changes"`, `state_topic` =
   `_hostname_changes_topic_for(topic_prefix)`, `state_class: "total_increasing"`, `icon: "mdi:swap-horizontal"`,
   `unit_of_measurement: "changes"`, `availability_topic: SHARED_AVAIL_TOPIC`, `payload_available: "online"`,
   `payload_not_available: "offline"`, `device` = the shared device block. Take `topic_prefix` as a parameter
   (do not re-derive the monitor's `topic_prefix` default logic a second time) — the caller already has it from
   `built["_topic_prefix"]`, so this keeps topic_prefix derivation as a single source of truth.
6. In `publish_mqtt()`, right after the existing `built = _build_discovery_payload(...)` block (where `payload`,
   `topic_prefix`, `state_topic`, `details_topic` are extracted), compute:
   ```python
   hostname_changes_payload = _build_hostname_changes_discovery_payload(monitor, slug, topic_prefix)
   hostname_changes_state_topic = _hostname_changes_topic_for(topic_prefix)
   hostname_changes_discovery_topic = (
       f"{discovery_prefix}/sensor/networktools_mdns_{slug}_hostname_changes/config"
   )
   ```
   Then, inside the existing `try:` block, right after the current `client.publish(details_topic, ...)` line and
   before the `log.debug(...)` call, add:
   ```python
   client.publish(hostname_changes_discovery_topic, json.dumps(hostname_changes_payload), retain=True)
   client.publish(
       hostname_changes_state_topic,
       str(result.get("hostname_change_count", 0)),
       retain=True,
       qos=1,
   )
   ```
7. In `main()`: add `state = load_state()` right after the "no monitors -> exit" early return. After the
   `try/except` block that produces `result` (both the success path via `run_monitor(monitor)` and the crash-fallback
   dict), add `_apply_hostname_stability(slug, result, state)` before `results.append(result)` — this applies
   uniformly to both a normal result and a crash-fallback dict (a crash dict has `state == "error"`, so the function
   just fills in the three default keys and leaves the baseline untouched). After the `for monitor in monitors:` loop
   ends, add `save_state(state)` right before the existing `write_output(results)` call — one load, one save per full
   pass, matching `arping_scan.py`'s cadence exactly (not a per-monitor write).

   ```bash
   # --- 9. Hostname stability (churn/rename-loop) across two polls ---
   echo "=== 9. Hostname stability: two polls with a mocked avahi-browse hostname flip ==="

   STABILITY_OPTIONS="$WORK/stability_options.json"
   cat > "$STABILITY_OPTIONS" <<EOF
   {
       "arping_hosts": [],
       "interface": "eth0",
       "log_level": "info",
       "mqtt_enabled": true,
       "mqtt_host": "core-mosquitto",
       "mqtt_port": 1883,
       "mqtt_username": "",
       "mqtt_password": "",
       "mqtt_discovery_prefix": "homeassistant",
       "mdns_monitors": [
           {
               "name": "stability_printer",
               "enabled": true,
               "service_types": ["_ipp._tcp"],
               "filter": [],
               "interval": 60,
               "timeout": 10,
               "topic_prefix": "homeassistant/monitor/stability_printer",
               "device_name": "Stability Printer"
           }
       ]
   }
   EOF

   STABILITY_PID=$(docker run -d --rm \
       --network container:"$MOSQ_PID" \
       -v "$STABILITY_OPTIONS:/data/options.json:ro" \
       -v "$MOCK_BIN:/mock_bin:ro" \
       -e "PATH=/mock_bin:/usr/local/bin:/usr/bin:/bin" \
       --entrypoint sleep \
       "$IMAGE:$VERSION" 600 2>/dev/null | tail -1)

   # Poll 1: mock avahi-browse still reports "brother.local" (unchanged from step 3)
   docker exec "$STABILITY_PID" python3 /usr/local/bin/mdns_scan.py > "$LOG_DIR/stability_poll1.log" 2>&1 || true

   # Rewrite the mock avahi-browse HOST column for poll 2 - simulates the avahi
   # hostname rename this feature must catch on the NEXT poll.
   cat > "$MOCK_BIN/avahi-browse" <<'EOF'
   #!/bin/sh
   cat <<'OUT'
   =;eth0;IPv4;Brother HL-L3270CDW series;_ipp._tcp;local;brother-renamed.local;192.168.178.50;631;"txtvers=1"
   OUT
   exit 0
   EOF
   chmod +x "$MOCK_BIN/avahi-browse"

   # Poll 2: same monitor, now sees the renamed host
   docker exec "$STABILITY_PID" python3 /usr/local/bin/mdns_scan.py > "$LOG_DIR/stability_poll2.log" 2>&1 || true

   sleep 1
   HOSTNAME_CHANGES=$(timeout 3 mosquitto_sub -h localhost -p 11883 \
       -t 'homeassistant/monitor/stability_printer/hostname_changes' -C 1 2>&1 || true)

   docker rm -f "$STABILITY_PID" 2>/dev/null || true
   STABILITY_PID=""

   A9=0
   if [ "$HOSTNAME_CHANGES" = "1" ]; then
       A9=0
   else
       A9=1
       echo "  A9 expected hostname_change_count=1 after the mocked hostname flip, got: $HOSTNAME_CHANGES"
       echo "  poll1 log:"; sed 's/^/    /' "$LOG_DIR/stability_poll1.log" 2>/dev/null || true
       echo "  poll2 log:"; sed 's/^/    /' "$LOG_DIR/stability_poll2.log" 2>/dev/null || true
   fi
   assert_ok "A9: hostname_change_count sensor increments after a hostname flip across polls" "$A9"
   ```
