<objective>
Move the ntfy GUI server onto the vendored skeleton (D-06) without changing a single API error code, route or response shape.

Prerequisite (D-01): execution starts only after Phase 24 is verified including the manual UAT on real HA ingress. Executed
in the worktree on branch `feat/ntfy-admin-ui-lib` (D-12); STATE.md, ROADMAP.md and state.json are never edited there.
Commits: English, no Co-Authored-By, stage by path. Requires plan 27-01 (the `ntfy/app/web/admin_ui/` copy must exist).

Decision from reading the code (D-06 "as far as it fits"): everything fits. The skeleton Router, Request, Download,
StaticFiles whitelist (same segment regex and extension set), ingress predicate, body rules (65536 bytes, JSON object,
content type), traceback-to-stdout 500 handling and `serve` shutdown are line-for-line what `ntfy/app/web/server.py` and
`ntfy/app/gui.py` implement today. The two gaps are handled in ntfy, not in the lib: the four ntfy-specific error codes are
added with the skeleton's `register_error_code`, and the `NtfyCliError` to API error mapping goes in through the skeleton's
`error_mappers`. Visible differences, all intended: security headers `Referrer-Policy` and a Content-Security-Policy on the
page and static files, and the `Server` header says AdminUi instead of NtfyGui (the skeleton's `make_server` has no
server-version argument; cosmetic, noted as lib friction, not worked around).

The CSP is safe for the ntfy page: plan 27-01 removed the only inline handler from index.html and the scanner rule csp plus the
static closure test guard it; plan 27-07 checks the header on the real container. `NTFY_GUI_CSP=off` stays as a documented
diagnostic escape hatch next to the existing `NTFY_GUI_PORT` and `NTFY_INGRESS_REMOTE` environment variables (the lib's own
`ADMIN_UI_CSP` pattern); it is never an add-on option and never used to get a green result.

Lib is copy-only (D-02): do not edit `ntfy/app/web/admin_ui/` or `admin-ui/`. If the skeleton lacks something ntfy needs, stop
with a `checkpoint:decision` "request additive lib change from the admin-ui manager" (`herdr agent prompt admin-ui "<need>"`,
pane `wH:p1`), then re-sync once with no other plan running. No blocking need was found while planning.

Output: contract, server adapter and entry point on the skeleton, with updated and new tests.
