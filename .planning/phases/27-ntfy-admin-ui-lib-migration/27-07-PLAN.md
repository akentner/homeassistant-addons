<objective>
Prove the migration in a real image and in real Home Assistant: extend the Docker verify scripts for the new layout and headers,
run them (one after the other), run the phase exit gate, and hand the visual and live-HA check to a human.

Prerequisite (D-01): execution starts only after Phase 24 is verified including the manual UAT on real HA ingress; that UAT is the
visual reference the checkpoint below compares against. Executed in the worktree on branch `feat/ntfy-admin-ui-lib` (D-12);
STATE.md, ROADMAP.md and state.json are never edited there. Commits: English, no Co-Authored-By, stage by path. Requires all earlier
plans (this is the only plan of the phase that runs Docker, so no two Docker verify runs share a wave).

Docker verify scripts build an image and start containers: never run them in two worktrees at the same time and never in parallel
with each other (container prefixes `ntfy-verify` and `ntfy-e2e`, scratch data under the system temp dir). The Dockerfile is not
changed by this phase (`COPY app/` carries both lib copies), so no hadolint run or separate Dockerfile build commit is needed; the
verify scripts build the image from the unchanged Dockerfile.

Lib stays copy-only (D-02): if the live check shows a lib problem (for example the CSP or the bridge misbehaving), do not patch the
copy. Report it to the admin-ui manager (`herdr agent prompt admin-ui "<need>"`, pane `wH:p1`) as a request for an additive change and
wait for a new lib version; the re-sync (`make sync-admin-ui ADDON=ntfy`) is then run once with nothing else running.

Output: updated verify scripts, green Docker runs, phase exit gate results, UAT record.
