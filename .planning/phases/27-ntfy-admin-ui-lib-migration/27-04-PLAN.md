## View rules that apply to every task

- Imports: `html`, `useState`, `useAsync`, `usePoll`, `toast`, `Modal`, `ConfirmDialog`, `Badge`, `CopyField`, `Loading`, `Field` from
  `../vendor/admin-ui/ui.mjs`; `get`, `post`, `put`, `del` from `../vendor/admin-ui/api.mjs` (keep the call shape `get("users")`, the
  registry test scans for it); `apiHref` from `../vendor/admin-ui/ingress.mjs`; `useT`, `useLang`, `tp`, `tError` from
  `../vendor/admin-ui/i18n.mjs`; `formatBytes`, `formatDateTime`, `formatNumber` from `../vendor/admin-ui/format.mjs`; shared pieces from
  `../components.mjs`; pure logic from `../lib/model.mjs`.
- Every component that renders text calls `const tt = useT();` and uses `tt("key", params)` or `tp("key", n, params)`. A key is a
  string literal or an index into an UPPER_CASE table whose values are literals; never a template string or a variable (R-06,
  enforced by `i18n.test.mjs`). Numbers go into texts as strings made with formatNumber.
- `export const meta = { id: "<id>", titleKey: "view.<id>" };` and a default exported view function.
- API failures: `ErrorNote error=${err}` inside forms and dialogs, `toast("error", tError(err))` for fire-and-forget actions;
  client-side validation messages use `FormNotice`. The backend `message` is never shown (R-14).
- Tables: `ScrollTable` with caption, `th scope="col"`; no inline styles, no storage, relative URLs only, state only as text nodes.
- Strings: keys go into `strings/manage.en.mjs` and `strings/manage.de.mjs` only, same keys and placeholders, real German. Fixed names
  agreed with plan 27-01: `tools.effective.admin`, `tools.effective.user_rule`, `tools.effective.everyone_rule`,
  `tools.effective.default` (selected through `effectiveExplain` and a literal table). Everything else is free inside the
  namespaces `health.`, `tools.`, `tokens.`, `data.`. Keep the English wording of the old views where possible.
- Tests live in `ntfy/tests/js/views_manage.test.mjs` (harness from plan 27-01; errors via `failures`, data via `fixtures`). A failure of
  `i18n.test.mjs` that names a key or file of plan 27-03's views is transient while that plan runs; re-run before concluding and
  do not fix it here.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GUI backend to browser DOM | token labels, prefixes, backup names and backend messages are untrusted text; token values are secrets |
| operator to destructive or outward-facing endpoints | resets, token revoke, test publish, exports that may include password hashes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-27-12 | Information disclosure | token values in the DOM or in toasts | high | mitigate | values live only in the Row reveal state and the creation dialog; tests assert no token-shaped text before Reveal and after Hide, and no toast or error text contains the value |
| T-27-13 | Tampering | reset actions without the exact typed phrase | high | mitigate | ConfirmDialog expected = RESET_PHRASES[kind] (R-04) and the confirm field the server requires; tests cover a wrong, a differently-cased and the exact phrase |
| T-27-14 | Information disclosure | export with password hashes | medium | mitigate | hashes are opt-in via the checkbox, the notice about storing the file like a password stays, the link is built with apiHref only and is relative; the test checks the href shape |
| T-27-15 | Tampering | test publish sends a real message to all subscribers | medium | mitigate | ConfirmDialog naming the topic before the POST; the ok:false outcome is reported as a failure; tests cover confirm and the 429 result |
| T-27-SC | Tampering | npm/pip/cargo installs | high | accept | no package installs in this plan |
</threat_model>
