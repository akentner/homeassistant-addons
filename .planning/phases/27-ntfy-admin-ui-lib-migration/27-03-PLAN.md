## View rules that apply to every task

- Imports: `html`, `useState`, `useAsync`, `toast`, `Modal`, `ConfirmDialog`, `Badge`, `Loading`, `Field` from `../vendor/admin-ui/ui.mjs`;
  `get`, `post`, `patch`, `put`, `del` from `../vendor/admin-ui/api.mjs` (keep the call shape `get("users")`, the registry test
  scans for it); `useT`, `useLang`, `tp`, `tError` from `../vendor/admin-ui/i18n.mjs`; formatters from `../vendor/admin-ui/format.mjs`;
  shared pieces from `../components.mjs`; pure logic from `../lib/model.mjs`.
- Every component that renders text calls `const tt = useT();` (so a language switch re-renders) and uses `tt("key", params)` or
  `tp("key", n, params)`. A key is a string literal or an index into an UPPER_CASE table whose values are literals; never a
  template string or a variable (the i18n test enforces this, R-06).
- `export const meta = { id: "<id>", titleKey: "view.<id>" };` and a default exported view function.
- API failures: `ErrorNote error=${err}` inside forms and dialogs, `toast("error", tError(err))` for fire-and-forget actions.
  Client-side validation messages use `FormNotice`. The backend `message` is never shown (R-14).
- Tables: `ScrollTable` with a caption, `th scope="col"` headers (the actions column gets a visible "Actions" header), no
  inline styles, no storage, relative URLs only, state only as text nodes.
- Strings: add keys to `strings/access.en.mjs` and `strings/access.de.mjs` only, same keys and placeholders, real German.
  Required key names fixed by plan 27-01: `users.protect.last_admin`, `users.protect.options_admin`, `users.protect.anonymous`,
  `users.protect.other` (selected through `protectionKind(reason)` and a literal table), `users.role.user`, `users.role.admin`,
  `users.role.anonymous`. Everything else is free inside the namespaces `users.`, `acl.`, `matrix.`.
- Keep the English wording of the old view where possible (for example "admin from options", "last admin").
- Tests live in `ntfy/tests/js/views_access.test.mjs` (harness from plan 27-01; set errors with `failures`, data with `fixtures`).
  `i18n.test.mjs` scans all views: a failure that names a key or file of plan 27-04's views is transient while that plan is
  running; re-run before concluding and do not fix it here.

The old views (`ntfy/app/web/static/views/users.mjs`, `acl.mjs`, `matrix.mjs`) are the behavioural reference; the demo
`admin-ui/app/web/static/views/crud.mjs` is the consumer pattern (Field, ErrorNote, ConfirmDialog with typed phrase, DataTable
alternative, toast with tError). API shapes: `GET api/users` gives `{users:[{name, role, tier, origin, provisioned, protected,
protected_reason, acl_count, token_count}]}`; `GET api/users/{name}` gives `{user, acl:[{topic, permission, origin}], tokens:[{id, prefix,
label, expires_at, last_access}]}`; `PATCH api/users/{name}` gives `{user, dropped_rules}` where dropped_rules is an integer;
`DELETE api/users/{name}` takes body `{confirm}`; `GET/PUT/DELETE api/acl` with `{user, topic, permission}` and query user/topic.
Error codes the UI can meet: bad_request, confirmation_required, not_found, conflict, protected, locked, db_unsupported, db_unavailable,
ntfy_error, internal_error, network_error.

| operator to destructive endpoints | deleting a user, dropping rules by promotion, rule delete |

| T-27-11 | Elevation of privilege | promoting a user to admin silently drops explicit rules | medium | mitigate | the confirmation that names user and rule count stays; the dropped count from dropped_rules is shown in the result toast; tests cover both |
