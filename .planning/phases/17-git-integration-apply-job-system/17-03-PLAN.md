<objective>
Build `internal/git`: the repo configuration type, the SSH-keyed clone and pull operations with their ref semantics and
startup backoff, and the stderr→`git_*` error classifier.

Purpose: GIT-02, GIT-03 and GIT-04 are all git-execution concerns, and they are the phase's only interaction with an
external network service. Isolating them in one package with an injectable command runner means the retry curve, the ref
semantics, and the whole error taxonomy are unit-testable without a network, an SSH server, or a real repo — which
matters because Phase 19 owns the live verification and this phase must ship provably-correct logic before then.

Output: 5 new files. `cd iac-runner && go build ./... && go vet ./... && go test ./internal/git/...` all exit 0.

Requirements satisfied by this plan:

- GIT-02: clone into `/data/repos/<name>/` when absent, leave existing directories untouched (the startup loop that
  calls `CloneAll` is wired in 17-07)
- GIT-03: `git pull --ff-only` (or the configured ref) using `/data/keys/<name>.key` + `/data/keys/known_hosts`, with
  non-fast-forward and auth failures as distinct typed errors
- GIT-04: typed `git_*` error codes with an Options-field hint and no stack traces

Locked decisions implemented here:

- D-10: when `ref` is set, clone and pull both land on that ref via `git fetch origin <ref>` + checkout
- D-11: when `ref` is empty, behavior is `git pull --ff-only` on the configured branch (default `main`)
- D-12: an explicit fast-forward-pull request against a pinned repo is refused with `git_ref_pull_incompatible`
- D-13: startup clone retries 3 times with 1s / 5s / 30s backoff, then logs `git_clone_failed` and gives up
- D-14: a repo whose working tree is missing or empty reports `git_clone_missing`

Explicitly OUT of scope: HTTP handlers (17-06), the startup loop and option parsing (17-07), run storage (17-04), tofu
execution (17-05). This package shells out to `git` only.

    A. `iac-runner/internal/git/repo.go`:

    ```go
    // Package git owns every interaction with the `git` binary: the
    // per-repo configuration read from add-on Options, the startup
    // clone into /data/repos/<name>/, the SSH-keyed pull, and the
    // translation of git's stderr into the stable git_* error_code
    // taxonomy (CONTEXT D-19).
    //
    // The package never talks HTTP and never touches /data/runs/ —
    // internal/runs owns run state, internal/jobq owns tofu execution.
    // Every git invocation goes through a CommandRunner so the retry
    // curve, the ref semantics, and the error classification are
    // testable without a network or an SSH server.
    package git

    import (
        "fmt"
        "regexp"
        "strings"
    )

    // defaultBranch is the branch used when a repo entry omits
    // `branch`. GIT-01 specifies "default main"; the HA schema cannot
    // express a default for a list-of-dict member, so the default
    // lives here (see 17-01 Task 1).
    const defaultBranch = "main"

    // repoNameRe mirrors the config.yaml schema regex for repo names
    // (17-01 Task 1). Re-validating in Go is deliberate defense in
    // depth: the name becomes a filesystem path segment under
    // /data/repos/ and a URL path segment in /v1/repos/{name}/pull.
    var repoNameRe = regexp.MustCompile(`^[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}$`)

    // RepoConfig is one entry of the `repos` Options list (GIT-01).
    // Field names match the HA schema keys exactly so main.go can
    // json.Unmarshal /data/options.json straight into []RepoConfig.
    type RepoConfig struct {
        Name   string `json:"name"`
        URL    string `json:"url"`
        Branch string `json:"branch"`
        Ref    string `json:"ref"`
    }

    // EffectiveBranch returns the branch to track: the configured
    // value, or "main" when unset (GIT-01 / CONTEXT D-11).
    func (r RepoConfig) EffectiveBranch() string {
        if strings.TrimSpace(r.Branch) == "" {
            return defaultBranch
        }
        return r.Branch
    }

    // Pinned reports whether this repo is pinned to an explicit ref.
    // When true, CONTEXT D-10 replaces pull semantics with
    // fetch + checkout and the `branch` field is ignored — the caller
    // is expected to log that at startup so an operator who set both
    // fields understands which one won.
    func (r RepoConfig) Pinned() bool {
        return strings.TrimSpace(r.Ref) != ""
    }

    // Validate checks a single entry from Options. Supervisor already
    // enforces the same rules via the config.yaml schema; this guard
    // covers hand-edited /data/options.json and keeps the invariant
    // local to the code that depends on it.
    func (r RepoConfig) Validate() error {
        if !repoNameRe.MatchString(r.Name) {
            return fmt.Errorf("git: invalid repo name %q: must match %s", r.Name, repoNameRe.String())
        }
        if strings.TrimSpace(r.URL) == "" {
            return fmt.Errorf("git: repo %q has an empty url", r.Name)
        }
        lower := strings.ToLower(r.URL)
        if strings.HasPrefix(lower, "http://") || strings.HasPrefix(lower, "https://") {
            return fmt.Errorf(
                "git: repo %q url must be an SSH url (git@host:path or ssh://…); "+
                    "https clones cannot authenticate with the deploy key at /data/keys/%s.key",
                r.Name, r.Name)
        }
        return nil
    }
    ```

    B. `iac-runner/internal/git/errors.go` — the typed error plus the classifier. Import
    `iac-runner/internal/contract` and use its constants:

    ```go
    // Error is the typed git failure every exported Manager method
    // returns. Code is a contract.ErrCodeGit* value (CONTEXT D-19),
    // Message is a single-line operator-facing summary, and Hint names
    // the Options field or credential path to fix (GIT-04).
    //
    // Error deliberately does NOT carry git's raw stderr: GIT-04
    // requires "no stack traces in the response body", and stderr from
    // a failed clone can echo the remote URL and occasionally token
    // material. The full stderr is logged server-side by the caller
    // through the scrubbing slog handler instead.
    type Error struct {
        Code    string
        Message string
        Hint    string
        wrapped error
    }

    func (e *Error) Error() string { … "git: <code>: <message> (hint: <hint>)" … }
    func (e *Error) Unwrap() error { return e.wrapped }
    ```

    Then the classifier. Implement as an ordered slice of `{pattern substrings, code, hint}` rules evaluated against
    `strings.ToLower(stderr)`; first match wins. Required rules, in this order:

    | stderr substring (lowercased)                                            | code                     | hint |
    |--------------------------------------------------------------------------|--------------------------|------|
    | `permission denied (publickey)`, `could not read from remote repository`  | git_ssh_handshake        | "check the deploy key at /data/keys/<name>.key (chmod 600) and that its public half is registered on the remote" |
    | `host key verification failed`, `no matching host key`                   | git_ssh_handshake        | "add the remote's host key to /data/keys/known_hosts" |
    | `could not resolve hostname`, `temporary failure in name resolution`      | git_dns_failure          | "check the host part of the repo `url` Options field and the add-on's DNS/Tailscale connectivity" |
    | `authentication failed`, `access denied`, `repository not found`          | git_unauthorized         | "the deploy key is valid but not authorized for this repo — check the repo `url` Options field and the key's repo access" |
    | `couldn't find remote ref`, `did not match any file(s) known to git`, `unknown revision` | git_ref_not_found | "check the `ref` (or `branch`) Options field for this repo" |
    | `not possible to fast-forward`, `non-fast-forward`, `need to specify how to reconcile`, `diverging branches` | git_non_fast_forward | "the local checkout has diverged from the remote; pin the repo with `ref` or delete /data/repos/<name>/ and let the add-on re-clone" |

    call site, or accept a name argument in the rule formatter — either is fine, but the emitted hint MUST contain the
    concrete repo name).
