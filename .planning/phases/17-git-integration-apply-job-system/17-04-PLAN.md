<objective>
Build the durable run store: the `/data/runs/{run_id}/` layout with lock-protected atomic metadata writes, the JSONL
output stream, read-time secret redaction with an audit count, the boot-time `interrupted` sweep, and age-based run
rotation.

Purpose: OBS-02, OBS-03 and SEC-03 all live here, and RUN-04's response body is assembled from this package. Making the
file-on-disk the source of truth (rather than an in-memory buffer) is what lets a restart-surviving run history exist at
all, and is explicitly required by OBS-03. Keeping redaction at read time (D-08) means the operator still has the raw
output under `/data` for `jq`-based debugging while the API surface stays safe.

Output: 8 new files. `cd iac-runner && go build ./... && go vet ./... && go test ./internal/runs/... -race` all exit 0.

Requirements satisfied by this plan:

- SEC-03: credential-pattern redaction of captured output before it is surfaced, plus a `redaction.audit` record
- OBS-02: per-run line-by-line capture to `/data/runs/{run_id}/output.log` with retention-driven deletion
- OBS-03: paginated `output_lines` with the file on disk as the source of truth, not an in-memory buffer
- RUN-04: the status / exit_code / started_at / finished_at metadata the run detail response is built from

Locked decisions implemented here:

- D-01: `/data/runs/{run_id}/meta.json` + `/data/runs/{run_id}/output.log`, written with flock + atomic rename
- D-02: on boot, any run still marked `running` becomes `interrupted`
- D-07: `output.log` is JSONL `{"ts":"<RFC3339>","stream":"stdout|stderr","line":"<raw>"}`
- D-08: redaction happens at read time, never at write time; a `redaction.audit` slog record counts redactions per run
- D-09 / D-24: output lines are written verbatim with no truncation; pagination bounds the API response instead
- D-25: `runs_retention_hours` rotation is what bounds worst-case disk usage

Explicitly OUT of scope: HTTP handlers (17-06), tofu execution and output production (17-05), the ticker's startup
wiring (17-07). This package is filesystem-only.
</objective>

    H. `Update(runID string, mutate func(*Meta) error) (Meta, error)` — the concurrency-critical path (D-01):

    ```
    lockFile, err := os.OpenFile(filepath.Join(Dir(runID), ".meta.lock"), os.O_CREATE|os.O_RDWR, 0o600)
    defer lockFile.Close()
    syscall.Flock(int(lockFile.Fd()), syscall.LOCK_EX)
    defer syscall.Flock(int(lockFile.Fd()), syscall.LOCK_UN)

    m, err := s.Load(runID)      // read INSIDE the lock
    if err != nil { return Meta{}, err }
    if err := mutate(&m); err != nil { return Meta{}, err }
    if err := s.writeMeta(m); err != nil { return Meta{}, err }
    return m, nil
    ```

    Use a SEPARATE `.meta.lock` file rather than locking `meta.json` itself — the atomic rename in `writeMeta` replaces
    the inode, so a lock held on the old `meta.json` fd would protect nothing. Put that reasoning in a comment; it is the
    subtle bug this design avoids.

    `syscall.Flock` is Linux-only, which is fine: the add-on ships as an amd64 Linux container (`arch: [amd64]`). Do NOT
    add a new module dependency for this — `syscall` is stdlib and the module currently has exactly one require
    (`chi/v5`).
