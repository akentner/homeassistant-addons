<objective>
Add a second, PDF-only virtual CUPS queue (`cups-pdf`) to the `cups` add-on, disabled by default, whose output is
picked up by a new decoupled background worker (`upload-worker.py`) and uploaded to a paperless-ngx instance's REST
API. The physical printer queue and cupsd itself must remain fully unaffected regardless of paperless-ngx's
availability.

Purpose: give the user a way to scan/print any document straight into paperless-ngx's document inbox from any
AirPrint-capable device, without touching the existing physical-printer path at all.

Output: a working, disabled-by-default `paperless_upload` feature — config schema, cups-pdf queue registration,
title-preserving sidecar mechanism, and a resilient upload worker with retry/backoff and failure visibility.
</objective>

<researched_correction>
IMPORTANT — a factual correction to CONTEXT.md's D-12, discovered by verifying cups-pdf's actual upstream C source
(cups-pdf.c, as packaged in Debian 3.0.2-3, functionally identical to Alpine's cups-pdf-3.0.2-r0) during planning:

D-12 states the job title is "only available in an environment variable inside its PostProcessing hook". This is
FALSE per the verified source: cups-pdf's `PostProcess` directive invokes the configured script via a plain
`system()` call with exactly THREE positional arguments — `$1` = the final absolute path of the generated PDF,
`$2` = the resolved username cups-pdf wrote the file as, `$3` = the original job-submitting username. No title
argument and no title-carrying environment variable are passed to the PostProcess script at all.

However, cups-pdf's OWN internal logic (`preparetitle()` in cups-pdf.c) ALREADY derives the final PDF's filename
directly from the print job's title (sanitized, extension-stripped) — with the `Label` directive controlling whether
a `job_<id>` disambiguator is added as a prefix (`Label 1`) or suffix (`Label 2`). This means the title is fully
recoverable from `$1`'s basename, with zero need for an env var that does not exist.

D-12's INTENT (a best-effort sidecar file written at print time, traveling with the PDF through every outbox stage,
read by the async worker, deleted on success) is preserved COMPLETELY unchanged. Only the exact mechanism by which
the hook script obtains the title text changes: from "read an env var" to "derive from $1's basename, after
stripping the `-job_<N>` suffix that `Label 2` appends for collision-safety in this add-on's single shared output
directory (D-05)". D-10/D-11/D-13/D-14 are all satisfied identically. This is a corrected implementation detail, not
a re-litigation of the design.
