<objective>
Scaffold the iac-runner/ HA Supervisor add-on following the established 4-file pattern with a multi-stage Go
Dockerfile (mirroring terraform-bridge's proven approach, but WITHOUT hassio_api and on port 8125 instead of 8124).
Implement the bearer-token authentication primitive (TokenStore + RequireBearer middleware + BindResolver + signal
handling + POST /v1/auth/rotate with 24h grace). The Plan 01 stub at /healthz always returns 200 with
HealthResponse{tofu_on_path:true, keys_chmod_600:true}; Plan 02 wires the real tofu + /data/keys/ chmod-600 checks
via a slog.Handler wrapper (SEC-02) and the state-backend interface (STBK-01..05); Plan 03 implements /v1/version.

Purpose: AUTHR-01..04 require a Go binary that authenticates requests and persists a token at startup. Every later v1.4
phase (17 git + apply jobs, 18 MQTT, 19 E2E) sits on top of this auth scaffold. The 4-file pattern + multi-stage
Dockerfile + 3-file version sync is the only way the existing add-on build infrastructure (make lint, make
validate-addons, make update-version) treats iac-runner like every other add-on in the repo. The signal handler
guarantees HA Supervisor's restart sequence (Supervisor sends SIGTERM then SIGKILL after 30s) drains cleanly.

./internal/auth/... all exit 0. python3 internal/validate-addon-config.py iac-runner exits 0. make validate-versions
includes iac-runner/. The Docker image builds end-to-end (verified by `docker build`).
