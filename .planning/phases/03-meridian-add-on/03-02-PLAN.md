**Key rules (per CONTEXT.md decisions):**

- D-12: Exactly two options — `log_level` and `port`; `log_level` default `"info"`, `port` default `3456`
- D-13: Port 3456 in `ports` section as `3456/tcp` (per MER-04)
- D-14: `url` must be `"https://github.com/akentner/homeassistant-addons"`
- D-18: `version` is `"1.26.6-0"` (subpatch format)
- `slug` must be `"meridian"` (matches directory name)
- `map` uses `addon_config` type pointing to `/opt/meridian/data` — this is the `/data` volume HA mounts for persistence
- All string values quoted per YAML convention
- `host_network: false` — port exposure is via `ports` declaration, not host networking

container). The run.sh symlink points `/root/.claude` → `/data/.claude` which HA maps. Double-check this is `/data` in
container terms — HA Supervisor maps `addon_config` to `/data` by default. Use `path: /data` if that is the HA
convention for addon_config map entries; otherwise use the actual target. Look at fritz-callmonitor2mqtt/config.yaml map
section for the correct path field value. </action> <verify> <automated>yamllint meridian/config.yaml</automated>

Create `meridian/run.sh` per D-05 through D-11.

**Shebang and structure (per D-09, CONVENTIONS.md):**

```bash
#!/usr/bin/with-contenv bashio
# shellcheck shell=bash
```

**Section 1 — Credential persistence symlink (per D-05):**

```bash
# Ensure .claude directory exists on persistent volume
mkdir -p /data/.claude

# Symlink /root/.claude to /data/.claude so OAuth token survives container restarts
ln -sf /data/.claude /root/.claude
```

**Section 2 — Credential check (per D-06, D-07):**

```bash
# Check for Claude credentials — required to start
if [[ ! -f /data/.claude/.claude.json ]]; then
    bashio::log.error "Claude credentials not found at /data/.claude/.claude.json"
    bashio::log.error ""
    bashio::log.error "To authenticate, follow these steps:"
    bashio::log.error "  1. Install the 'Terminal & SSH' add-on from the HA add-on store"
    bashio::log.error "  2. Open the terminal and run: docker exec -it \$(docker ps -qf name=meridian) sh"
    bashio::log.error "  3. Inside the container run: claude login"
    bashio::log.error "  4. Complete the OAuth flow in your browser"
    bashio::log.error "  5. Restart this add-on"
    exit 1
fi
```

**Section 3 — Read config and export env vars (per D-08, D-12):**

```bash
# Read add-on configuration
MERIDIAN_LOG_LEVEL=$(bashio::config 'log_level')
MERIDIAN_PORT=$(bashio::config 'port')

# Bind to all interfaces so LAN and Tailscale can reach the proxy (per D-08)
MERIDIAN_HOST="0.0.0.0"

export MERIDIAN_LOG_LEVEL
export MERIDIAN_PORT
export MERIDIAN_HOST
```

**Section 4 — Launch (per D-10, D-11):**

```bash
bashio::log.info "Starting Meridian proxy on port ${MERIDIAN_PORT}..."

# Hand off to S6 — exec replaces shell process; HA restart policy handles recovery
exec node "${WORKING_DIR}/dist/cli.js"
```
