Rule catalog to write into `DOCS.md` (id, rule, enforced by; the executor writes full sentences, this is the content):

- R-01 Ingress gate on every request: peer 172.30.32.2 plus `X-Ingress-Path`, else 403 `ingress_only`, every method and
  path; never publish the GUI port. Enforced by `test_skeleton_server.py` gate tests and `internal/verify-admin-ui-scaffold.sh`.
- R-02 URLs are relative (no leading slash, no scheme); download links via `apiHref`; requests only through the lib client.
  Enforced by scanner rule `urls` and `api.test.mjs`.
- R-03 Never put state into markup: text nodes only; no raw-markup APIs, eval, string timers. Enforced by scanner rule
  `markup` and component tests with hostile text.
- R-04 Destructive actions need type-to-confirm (`ConfirmDialog` with `expected`; the server answers `confirmation_required`
  without the phrase). Enforced by ui tests and `test_demo_api.py`.
- R-05 The runtime is vendored and pinned by SHA-256: no CDN, no npm, no build step. Enforced by scanner rule `vendor` and
  `test_static_rules.py`.
- R-06 Every user-visible string goes through `t()`/`tp()`; de/en key and placeholder parity; no dynamic keys. Enforced by
  `i18n.test.mjs`.
- R-07 Dates, times, numbers, bytes and relative times via `Intl` (`format.mjs`). Enforced by `format.test.mjs` for the lib,
  review for add-on code.
- R-08 Colours only from tokens, both themes, text contrast at least 4.5:1, `prefers-color-scheme` is the default. Enforced
  by `test_css.py` (tokens, contrast, hex hygiene); extends D-16, which kept contrast manual (PD-03).
- R-09 a11y minimum: dialog role with focus move, trap and return, `aria-live` toasts, `role=alert` errors, labelled
  controls, `th scope`, visible focus, reduced motion. Enforced by `a11y.test.mjs`, `ui.test.mjs`, `test_css.py`.
- R-10 Storage keys are namespaced (`admin-ui:lang`, `<slug>:<key>`) and accessed in try/catch. Enforced by scanner rule
  `storage` and `i18n.test.mjs`.
- R-11 No third-party scripts; no inline script, handler or style attribute (CSP compatible); the CSP header is a default,
  promised only after spike item S9. Enforced by scanner rule `csp`; status unverified until S9 (PD-07).
- R-12 Test duty: every GUI ships node tests for its views plus i18n parity and runs them in CI. Enforced by the CI job for
  admin-ui (plan 26-09); existing add-ons follow in their migration phases.
- R-13 HA theme and layout are progressive enhancement: own tokens and fixed layout always work; theme-sync and bridge only
  enhance; failure means own theme. Enforced by `theme_sync.test.mjs`, `ha_bridge.test.mjs`; live behaviour by the spike.
- R-14 The backend returns stable error codes; the UI maps `errors.<code>`, unknown codes show generic text plus `[code]`;
  the backend `message` is never primary text. Enforced by `i18n.test.mjs` (`tError`) and `test_demo_api.py`.
- R-15 Lib and skeleton sources change only in `admin-ui/`; consumer copies are never hand-edited; the drift check fails on
  mismatch. Enforced by `make check-admin-ui-sync` and `test_sync.py`.

Migration facts for D-07 (from CONTEXT and research): ntfy has `lib/api.mjs`, `lib/ui.mjs`, `lib/model.mjs`, `app.css`,
`vendor/` and its own tests that duplicate the lib; its switch-over drops those duplicates, copies the lib with `make
sync-admin-ui ADDON=ntfy`, replaces English literals by strings and accepts the new contrast tokens (the look changes
slightly, research open question 7). `secrets-sync` is a stdlib server with a 540-line vanilla-JS GUI using
`window.confirm()`: full rewrite on Preact/htm, ConfirmDialog instead of confirm, tests added to CI. `haos-monitor` is a
busybox/CGI GUI: rebuild on the blueprint stack (Python server plus Preact), decide whether it gets the ingress gate; it is
also missing from `internal/base-image-config.yaml` (PD-09, follow-up only). Making ntfy and secrets-sync frontend tests
part of CI belongs to those phases (D-17).
