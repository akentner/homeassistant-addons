<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Parent window state (theme colours, bridge messages, route) -> spike page | produced by HA or a user theme; validated by the lib modules, still external |
| Spike result block -> clipboard -> repository docs | results are pasted by a human into DOCS and planning files in a public repository |
| `api/whoami` -> spike page | identity headers of the viewer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-26-47 | Information disclosure | `buildResult` / `redact` | high | mitigate | pure redaction function removing identity, URL, host and token-like data at any depth; result built from an allow-list of fields; test with a populated hostile fixture asserting absence of name, user id, URL, hostname and token; instruction text lists what may be pasted |
| T-26-48 | Tampering | spike buttons (navigate, kiosk policy, handleSafeArea) | low | mitigate | fixed `/config` path, three fixed policy values, user-triggered only; bridge validates every outgoing message again |
| T-26-49 | Tampering (XSS) | rendering parent-derived strings | medium | mitigate | skipped reasons, routes and raw values are rendered as text children only, colours only after parsing; hostile-string tests; scanner rule `markup` |
| T-26-50 | Information disclosure | S10 storage probe, S9 CSP listener | low | mitigate | probe uses its own namespaced key and removes it, never reads other keys; CSP listener stores only directive names and a URI category, never full blocked URIs |
| T-26-SC | Tampering | package installs | high | accept | No package installs in this plan |
</threat_model>
