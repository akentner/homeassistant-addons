<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lib source -> lock -> consumer copies | the lock is the pin that makes silent changes visible |
| Contributor machines -> hooks | `language: system` hooks run repo scripts locally |
| Final container image -> Supervisor network | what the image serves is what runs on HA's origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-26-51 | Tampering | `lib.lock` regenerated blindly | medium | mitigate | lock refreshed only after the full suites pass; the lock diff is reviewed together with the lib diff in the same commit; CI and hook re-check it, so an unreviewed lib edit without matching lock is red |
| T-26-52 | Elevation of privilege | `language: system` hooks | low | accept | hooks run stdlib Python scripts that live in the repository under review, same trust as the rest of the repo and as the existing local hooks |
| T-26-53 | Tampering / Information disclosure | final image content | medium | mitigate | extended smoke checks the gate, served file set (VERSION and non-whitelisted files 404), vendored hash, CSP and absence of frame-blocking header, error bodies without exception text |
| T-26-54 | Information disclosure | DOCS and CHANGELOG reconciliation | low | accept | descriptive text only; the docs test forbids no content but the plan forbids hostnames and tokens by instruction |
| T-26-SC | Tampering | package installs | high | accept | No new packages; `uv run --with pytest` is the established runner and the CI pin was human-verified in plan 26-09 |
</threat_model>
