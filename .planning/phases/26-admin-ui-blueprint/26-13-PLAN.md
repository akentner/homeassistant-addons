<objective>
Run the live spike of D-14 and let the evidence decide what the rules guarantee. A human runs the spike page of the demo
add-on on a real Home Assistant instance in every context of the matrix and returns the redacted result blocks; this plan
then records the results in `DOCS.md` and a dated log and adjusts rules, statuses and (only where the data contradicts the
design) code.

Purpose: the HA iframe protocol, the parent theme access and the CSP behaviour are undocumented or unverified (research
A1-A11); the user decided that the spike results fix what the blueprint promises. Nothing in DOCS may claim more than a run
showed.

Output: spike log, updated DOCS (table, header, rules, integration limits), updated statuses in the rules view, and any
necessary adjustment of the bridge default policy, origin check or CSP, with tests and a refreshed lock.
