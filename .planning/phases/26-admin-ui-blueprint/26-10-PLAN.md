<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fake API responses -> demo views | item names, notes and error bodies are untrusted text |
| URL hash -> dynamic `import()` | the route id selects which module is loaded |
| Language and theme state -> storage and DOM | shared origin with HA |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-26-43 | Tampering (XSS) | gallery, tokens, language, CRUD rendering | high | mitigate | all values as text children of lib components, no raw-markup API (scanner rule `markup` over the demo), hostile-name tests in list, modal and confirm dialog |
| T-26-44 | Tampering | destructive delete in CRUD | medium | mitigate | `ConfirmDialog` with `expected` equal to the item name plus server-side `confirmation_required`; tests for wrong phrase, exact phrase and the protected item |
| T-26-45 | Denial of service | health poll, slow request | low | mitigate | poll every 15 s only while the page is visible and stopped on unmount; the slow endpoint is clamped server-side to 2 s |
| T-26-46 | Spoofing / Elevation | hash route to dynamic `import()` | medium | mitigate | `parseHash` accepts only ids present in `VIEWS`, the import keeps a literal relative prefix, a failing import is shown as `errors.view_failed`; test with a hostile hash such as `#/../../x` |
| T-26-SC | Tampering | package installs | high | accept | No package installs in this plan |
</threat_model>
