<objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application data (names, API text, errors) -> components | any string may be hostile (`<b>`, script-like text) |
| User input -> destructive action | one click must not delete data |
| Bridge store (HA postMessage state) -> Topbar | state originates from validated messages but is still external |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-26-35 | Tampering (XSS) | all components | high | mitigate | text nodes only, no raw-markup API in the lib (scanner rule `markup`), hostile-string tests per component, `href` values only from `apiHref` or fixed `#/id` routes |
| T-26-36 | Tampering | `ConfirmDialog` | medium | mitigate | confirm disabled until the exact phrase, exact comparison (`confirmMatches`), Cancel focused first for danger actions, failures kept visible in the dialog; server-side `confirmation_required` backs it (R-04) |
| T-26-37 | Denial of service (a11y lock-in) | `Modal` focus trap | low | mitigate | Escape always closes, trap wraps only inside the dialog, focus restored on close; tested both directions |
| T-26-38 | Information disclosure | toasts and `ErrorNote` | low | mitigate | only localized text and codes are shown, never raw backend messages or stack traces; toasts hold final strings and expire after 5 s |
| T-26-39 | Spoofing | `CopyField`, clipboard | low | accept | writes only the visible value the user asked to copy; fallbacks use the user-initiated select path |
| T-26-SC | Tampering | package installs | high | accept | No package installs in this plan |
</threat_model>
