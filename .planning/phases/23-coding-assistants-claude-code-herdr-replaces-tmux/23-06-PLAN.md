<plugin_facts>
Established while planning (static reads plus herdr runtime checks in a scratch container):
- Plugin ids: subagent-watch `subagent.watch` (actions open, setup, remove; panes viewer), web-service
  `imontes.herdr-web-service` (startup hook plus actions start, stop, status, setup, uninstall), claude-limits
  `martin.claude-limits` (startup hook starting a detached poller, actions show, restart; pane detail).
- `herdr plugin link DIR` needs an absolute path, works without a server, is idempotent and enabled-by-default; it skips
  `[[build]]`. The plugin config dir is `$XDG_CONFIG_HOME/herdr/plugins/config/<id>`; the plugin STATE dir is
  `$HOME/.local/state/herdr/plugins/<id>` (not under /data), so pid files and the web-service login sessions are
  ephemeral per container, which also avoids stale pid files after a restart.
- claude-limits needs `jq` and `curl` (installed) and reads `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.credentials.json`; its
  poller writes `poller.log` and `poller.pid` into its state dir. Without credentials it logs and keeps running.
- subagent-watch needs Node >= 22 (the image has 24.x via NodeSource); `sh bin/run.sh scripts/setup.mjs --dry-run` prints the
  setup changes without writing anything.
</plugin_facts>
