run.sh with the add-on environment, route SSH and the web terminal through one attach-or-create wrapper so both share a

user-visible surface (TOOLS.md, info.html, MOTD, versions, backup_exclude).

<herdr_facts>
Verified in a scratch container with herdr 0.9.3 while planning (do not re-derive):
- `herdr status --json` prints `.server.running` (true/false) and never starts a server; `herdr workspace list` returns
  `.result.workspaces[]` (fields workspace_id, label); `herdr workspace create --cwd PATH --label NAME --no-focus` returns
  the created workspace and root pane; `herdr pane list` returns `.result.panes[]` with `pane_id`, `cwd`; `herdr pane run
  PANE COMMAND` types a command plus Enter into a pane; `herdr plugin link DIR` works without a running server and is
  idempotent.
- A bare `herdr` launches or attaches to the persistent default session and auto-starts a detached server if none runs
  (the wrapper must therefore never call it unless a server is verified running). The server's environment becomes every
  pane's environment; `SHELL` selects the pane shell. The socket lives at `$XDG_CONFIG_HOME/herdr/herdr.sock`.
- After `kill -9` on the server the next server starts with an EMPTY session (no restore); a bare client then opens a
  workspace in $HOME. After a clean `herdr server stop` the session (session.json, session-snapshots/) is restored.
- The release binary is static: `herdr-linux-x86_64` sha256 `18a8dc65f1c2fa485884344356dea1cfd911c6f06cf46fa78e193f4087f4dba7`,
  `herdr-linux-aarch64` sha256 `4de7aa3e25678812e92960de64f7c2aaa1bca1f0f80a3c5e559837e231e1f5c0` (GitHub release v0.9.3 digests,
  re-checked while planning).
- Default keys: prefix `ctrl+b`, detach `prefix+q`, help `prefix+?`, new tab `prefix+c`, workspace picker `prefix+w`.
</herdr_facts>
