<exposure_notes>
For the threat model and the DOCS text (facts established while planning):
- nginx listens on 8099, the ingress port; the add-on publishes only 2222 and 4096. HA ingress is admin-gated by default
  (panel_admin). Other containers on the hassio network can in principle reach nginx:8099 directly; that exposure already
  exists for the writable root shell at /terminal/. For /services/ the plugin's own password login (closed with 503 until a
  password exists) is the gate in that case, because nginx rewrites Host and Origin to loopback values so the plugin's
  allow-list accepts ingress traffic.
- The plugin sets `Secure` and HSTS only when X-Forwarded-Proto: https arrives from a loopback peer; nginx must not set
  that header. Its session cookie is `hwv_session`, Path=/, HttpOnly, SameSite=Strict (it is therefore also sent to HA core
  paths on the same origin; harmless but worth one sentence in the docs).
- Login sessions live in the plugin STATE dir under /root/.local/state (ephemeral): users log in again after an add-on
  restart. The password hash lives in the plugin CONFIG dir under /data/.config/herdr/plugins/config/imontes.herdr-web-service
  (persistent).
</exposure_notes>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> HA ingress (admin session) -> add-on nginx :8099 | the first gate is HA; nginx then rewrites Host/Origin to loopback values |
| other containers on the hassio network -> nginx :8099 | not authenticated by HA; reaches /terminal/ today and /services/ after this plan |
| add-on options -> run.sh -> plugin set-password | the web login password crosses from the options store into a process and an auth file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-23 | Spoofing | nginx overriding Host and Origin so the plugin's loopback-only allow-list accepts ingress traffic (weakens the plugin's CSRF-origin check for requests through nginx) | high | mitigate | the plugin's password login stays mandatory (503 until a password exists, argon2id), the session cookie is HttpOnly + SameSite=Strict, `/ws` and the session API require that cookie (asserted through nginx by the harness); the spike showed the allow-list still rejects a spoofed Host on direct access; HA ingress (admin-only) is the outer gate |
| T-23-24 | Spoofing | replacing the plugin's CSP (frame-ancestors 'none') so the page can be framed by the landing page | medium | mitigate | replacement CSP keeps `frame-ancestors 'self'` (never `*`), the plugin's own header is hidden so exactly one CSP is sent; harness asserts both |
