<objective>
Register the add-on's MCP servers for Claude Code at user scope, mirroring what OpenCode already receives, by merging only
the `.mcpServers` key of `/data/.claude.json` with "existing entries win" semantics (ROADMAP Phase 23 locked decision).

The first task is a tracer for the capability: one shared merge helper plus the `mcp_servers` block, proven end-to-end by
the harness against a real run.sh. The second task adds the zigbee2mqtt and mycli call sites.

Purpose: the user gets the same tool surface (ha-mcp, fff, zigbee2mqtt, mariadb-*) in Claude Code as in OpenCode without
hand-registering anything, while Claude's own state and user edits stay untouched.

Output: `claude_mcp_merge` in run.sh and its three call sites; harness scenarios `mcp-servers` and `mcp-integrations`.
</objective>

Defaults chosen for research questions (recorded here so the executor and the verifier do not re-ask):

- Default 6 (stale MCP defaults, 23-RESEARCH.md Pitfall 8): NO ledger file. "Existing entries win" freezes the first
  value the add-on ever wrote (for example the ha-mcp URL) until the user edits or removes the entry. This is a documented
  limitation (documentation lands in plan 23-08), not something to engineer around now. The harness asserts the
  user-edit-wins half of the rule only.
- Pre-existing defect, deliberately NOT fixed here: run.sh appends the MQTT_* / MYCLI_* exports to
  /etc/profile.d/00-coding-assistants.sh and to the fish conf.d file BEFORE those files are truncated and rewritten later in
  the script, so the appended lines are lost. The existing OpenCode zigbee2mqtt entry carries no env and depends on those
  lost exports. For Claude the zigbee2mqtt entry therefore carries an explicit env object. Fixing the ordering is out of scope;
  record it as a deferred item in the SUMMARY.
- The config.yaml schema for `mcp_servers` currently has only name/type/command/url while DOCS.md documents args/env. Keep
  the tolerant `(.args // [])` / `(.env // [])` mapping (matches the documented contract, costs nothing); do not change the
  schema in this plan.
