<objective>
Prove, before anything is wired into the image, that herdr-web-service can be mounted under a sub-path behind HA ingress
with a small build-time patch plus an nginx block, and capture the patch, the validated nginx block and the exact build
sequence. The research found that the shipped SPA hard-codes root-absolute URLs (`/api/...`, `/ws`, `/assets/...`,
`/sw.js`) and that the server sends `frame-ancestors 'none'` and enforces a Host/Origin allow-list, so a bare
`proxy_pass` yields a broken page (23-RESEARCH.md Summary item 3, Pitfall 5). The plugin was only read statically
(assumption A1); this plan is the first time it runs.

The first task is the tracer for the whole web-service path (patch -> build -> herdr startup hook -> inner nginx ->
emulated ingress -> login -> WebSocket) in a throwaway container. The second task records the verdict and the reusable
findings.

Purpose: user decision 3 requires "the build-time patch plus nginx block, WITH a spike/verify task". D-05 (expose the
service at /services/ without a new port) is only deliverable if this path is real.

Output: patch, re-runnable spike script, spike document with a GO / NO-GO verdict.
</objective>

<spike_facts>
Verified statically while planning (the spike must confirm them by running, not assume them):
- Manifest: `[[build]]` runs only on `herdr plugin install`; `herdr plugin link` skips it, so the build is `bun install
  --frozen-lockfile` and `bun run build` (script `bun --bun vite build --config web/vite.config.ts`) run by us. `[[startup]]`
  runs `sh scripts/bun.sh scripts/plugin.ts start` after every herdr server start; `start` spawns the bun server detached
  (no systemd needed) on `HOST`/`PORT` (defaults 127.0.0.1 and 7340), writes a pid file and waits for `/api/health`, and
  exits 1 if `dist/index.html` is missing. `scripts/bun.sh` finds bun via `command -v bun`.
- Password: `bun scripts/plugin.ts set-password` reads one line from a pipe when stdin is not a TTY and stores an argon2id
  hash in `<HERDR_PLUGIN_CONFIG_DIR>/auth.json`; rules: at least 6 characters, a symbol, a number, an uppercase letter.
  Until that file exists `POST /api/auth/login` answers 503 (`setup_required`). `herdr plugin config-dir
  imontes.herdr-web-service` prints `$XDG_CONFIG_HOME/herdr/plugins/config/imontes.herdr-web-service` without a server.
- Access policy (server/access.ts): allowed Host names are localhost, 127.0.0.1, ::1 (+ PUBLIC_URL host); `/ws` REQUIRES an
  allowed Origin (http://127.0.0.1:7340 style); in `local` mode login is allowed only when the TCP peer is loopback (nginx
  on 127.0.0.1 qualifies); `Secure`/HSTS only when `X-Forwarded-Proto` is https from a loopback peer, so nginx must NOT set
  that header; the response CSP is `... frame-ancestors 'none'; base-uri 'none'`; the session cookie is `hwv_session`,
  `Path=/; HttpOnly; SameSite=Strict`.
- Gating (server/index.ts): `/api/health` and `/api/session` are answered without a session (`/api/session` returns `authenticated` and
  `setup_required` flags); every other `/api/*` route and `/ws` need the session cookie (401 otherwise, e.g. `/api/roster`).
- Client edit points (research, confirmed by the dossier): `web/vite.config.ts` (add `base: "./"`), `web/src/api.ts` (`call()`
  fetches root-absolute `/api/...` paths), `web/src/roster.ts` lines 47-48 (WebSocket URL from `location.host` + `/ws`),
  `web/src/main.tsx` lines 12-13 (service worker registered at `/sw.js`), `web/src/InstallBanner.tsx` line 18 (`/icon-192.png`),
  `web/src/ChatView.tsx` lines 467-468 (`/api/uploads/...`), `web/index.html` (manifest and icon links). The router uses
  `location.hash`, which is sub-path safe.
</spike_facts>
