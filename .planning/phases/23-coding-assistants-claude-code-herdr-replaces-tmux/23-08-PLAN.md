<doc_facts>
Facts to document, established while planning and verified in earlier plans (re-check each against the shipped files before
writing it; the shipped files win):
- Claude: `claude update` replaces the version under `/data/.local/share/claude/versions` and `~/.local/bin/claude` points
  into that directory; the image only seeds `/opt/claude-initial`; the newest of seed/persisted wins at every start. Auth:
  options `claude_code_oauth_token` / `anthropic_api_key` export `CLAUDE_CODE_OAUTH_TOKEN` / `ANTHROPIC_API_KEY` into the
  process environment of every process the add-on starts (herdr panes included) and never into a file; with both set the API
  key wins and interactive Claude asks once to approve it; an `env_vars` entry with the same name overrides the option.
  Otherwise use `claude login`; credentials live in `/data/.claude/.credentials.json`.
- MCP: `.mcpServers` of `/data/.claude.json` receives the add-on servers; an existing entry is never overwritten, so edits
  survive but also freeze old add-on values; to refresh an entry delete it with `claude mcp remove NAME` (or edit the file)
  and restart the add-on.
- herdr: default prefix `ctrl+b`, detach `prefix+q`, help `prefix+?`, new tab `prefix+c`, workspace picker `prefix+w`;
  the first attach shows herdr's onboarding dialog until dismissed; `herdr server stop` restarts the server within seconds
  (run.sh respawns it); `herdr update` replaces the binary only for the current container (bump the pinned ARG instead);
  escape hatch for SSH: run `CODING_ASSISTANTS_NO_ATTACH=1 bash -l` as the remote command or use `bash --noprofile`.
- Plugins (paths `/opt/herdr-plugins/<repository-name>`): subagent-watch `herdr plugin action invoke subagent.watch.open`
  opens the popup for the pane it is invoked from; `subagent.watch.setup` is the user-run opt-in that edits ~/.claude/settings.json
  and herdr's config.toml (backups are made, see the plugin README); claude-limits needs `[ui] tab_bar_right` with
  `{ type = "command", command = "/opt/herdr-plugins/herdr-claude-limits/bin/status.sh", interval_seconds = 10 }` and optionally
  `[[keys.command]]` with `key = "prefix+u"`, `type = "plugin_action"`, `command = "martin.claude-limits.show"`, followed by
  `herdr server reload-config`; it reads `/data/.claude/.credentials.json` and therefore works only after an interactive
  `claude login`; web-service actions `imontes.herdr-web-service.status|start|stop`.
- Web UI: `/services/` through ingress (Services tab), login password from `herdr_web_password`, hash persistent, login
  sessions not persistent across add-on restarts, session cookie also sent to other paths of the HA origin, blast radius equal
  to the writable web terminal, reachable from other containers on the hassio network at port 8099 like the terminal is.
</doc_facts>
