<objective>
Fix the root of both failed 21-VERIFICATION truths inside the add-on, on the evidence of Plan 21-04: make avahi's host-name
claim observable (its log was going to a dead syslog sink), make cupsd publish only AFTER the claim has settled, retry
a lost claim a bounded number of times, and never let the add-on run unconfigured when generate_config.py fails (CR-02,
with WR-04's trailing-newline validation hole closed in the same pass). Also complete D-10: `use-ipv6=no` alone leaves
the host's IPv6 ULA published as an AAAA record over IPv4 (21-04 finding 4), which is the exact resolution ambiguity D-10
was meant to remove.

Purpose: 21-VERIFICATION truth #13 (fixed hostname survives restart/update) and #14 (the `_ipp._tcp` service resolves
from a LAN client). The published instance `Brother-MFC-7460DN @ cups` next to a daemon named `cups-2.local` shows cupsd
registered under a name avahi later dropped; ordering cupsd after a settled claim removes that mechanism whether or
not the fixed name can be won.
Output: `cups/avahi-guard.sh` (sourced library), run.sh and generate_config.py wiring, a Dockerfile COPY, a docker-based
guard verifier and a fast host-side hardening verifier.

Spec-less probe fallback: visibly SKIPPED -- ad-hoc phase whose requirements are the CONTEXT.md decisions D-01..D-13;
no SPEC.md exists for this phase.

Design decisions taken here (Claude's discretion, D-11 leaves the recovery policy open; all reversible, one code
branch each): (a) avahi runs in the foreground of a backgrounded job so stderr is the add-on log; (b) readiness is read
from the D-Bus API (GetState/GetHostNameFqdn), which cupsd itself depends on, not scraped from process titles; (c) retry
schedule 30 s then 90 s -- the cumulative wait before the last attempt reaches 120 s plus settle time, which outlasts
the 120 s default TTL of mDNS host records in case a peer or proxy still holds the previous instance's records; (d)
after the last attempt the add-on continues under the actual host name
with a loud ERROR instead of exiting, because a stopped print server is worse than a renamed one, and the Supervisor
watchdog would only restart-loop an exit.
</objective>
